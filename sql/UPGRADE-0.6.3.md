# AgentBot 0.6.3 升级说明

适用起点：已完成既有数据库升级的完整 0.6.2 业务库。更早版本先完成
`UPGRADE-AUTOMATIC.md` 登记的历史起点，不能通过重新初始化替代迁移。

## 顺序与数据影响

1. 备份业务数据库、启动配置及独立队列，停止共享数据库的旧实例。
2. 安装 0.6.3；完整包同时包含 MySQL、SQLite 初始化及适用增量资源。
3. 启动主服务、桌面后端或独立 worker 前，自动读取所选业务库并执行登记清单。
   可提前运行 `agent-bot database upgrade`；命令成功退出且结构核验通过才表示迁移完成。
4. 在 `call-record-classification-v1` 后执行 `persistent-agent-v1`，对应
   `persistent-agent.sql` / `persistent-agent.sqlite.sql`，创建持续身份、任务、
   情节、记忆提案及审计五表与索引、外键。更早登记增量按清单补齐，不扫描历史 SQL。
5. 核对 `agent_bot_schema_version` 为 `0.6.3`，所有登记流水为 `applied`。
   字段、唯一键、调度索引及外键须通过实际结构核验，已有成功流水也会再次核验。
   再次执行升级应报告零项变更。新身份保持暂停，不会因升级开始付费推理或主动发送。

迁移不删除或重建旧表，不重写已有配置、角色、记忆、任务、密钥及登录资料。
新数据库仅执行对应完整初始化脚本即可获得当前结构。

## 更新失败

SQL 缺失、旧流水校验和改变、结构不符合预期、升级锁不可用或 SQL 执行失败时，
启动失败并返回非零状态；不得继续加载运行配置或对外提供新服务，也不切换数据库后端。
安装器替换程序文件不等于业务数据库已迁移，静默安装不会自动启动服务；
迁移在更新后的首次启动完成。不要在迁移前显示业务就绪。

SQLite 的增量、核验和版本推进处于同一事务。MySQL DDL 可能已经提交，
命名锁覆盖整个过程；`persistent-agent-v1` 使用明确可重入的建表脚本，
中断后重启继续，全部核验通过后才推进最终版本。若同名表结构已损坏，
停止启动并根据备份修复，不删除表后强行重跑。

## 回退

保留原发行包和升级前一致备份。旧程序发现更高数据库版本时应拒绝启动，
不能直接降低版本记录；完整回退须停服并恢复匹配备份，不自动降级。
